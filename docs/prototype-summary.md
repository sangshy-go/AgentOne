## 1. 为什么重做

现有 Skill 中心是「技能资产管理」视角：列表 + 创建 + 调试并列，面向的是技术人员。
而产品定位是**中小企业所有工种**（市场/销售/客服/人事/财务/法务/行政/数据/IT）都能用的技能平台——
业务用户带着业务问题来，需要的是「能力发现」：找到一个能解决我问题的技能，试一试，用上。

核心转变：

| 维度 | v1（现状） | v2（本原型） |
|------|-----------|-------------|
| 组织视角 | 技术形态（内置/API/自定义） | 工种导航（10 个工种 chip） |
| 首要动作 | 浏览资产列表 | 广场发现 → 详情 → 试用 → 启用 |
| 调试 | 顶级 Tab（三步向导） | 降级为详情抽屉内「试一试」行内动作 |
| 创建 | 双轨（表单/API） | 五入口（模板/空白/内容导入/脚本包/API） |
| 技能形态 | 仅内容/API | 增加 Claude Skills 形态（SKILL.md + scripts + resources） |

## 2. 功能列表（原型已实现）

### 2.1 技能广场（发现视角）
- 工种导航 chips：全部/市场/销售/客服/人事/财务/法务合规/行政/数据分析/IT 集成，点击筛选
- 搜索：名称/描述/关键词模糊匹配，实时过滤
- 官方精选区：默认展示，筛选时自动隐藏
- 技能卡片网格：图标 + 名称 + 一句话卖点 + 工种标签 + 来源标识（官方/自建/导入/内置/MCP）
- 空态：搜索无结果时给出「换关键词 / 按工种浏览 / 创建技能」出路

### 2.2 技能详情抽屉
- 它能做什么：能力描述
- 你可以这样问：对话气泡形式的示例提问（**发现型设计的签名元素**，让业务用户秒懂用法）
- 技能包文件：脚本包技能展示 SKILL.md + scripts + resources 文件树，并标注「脚本暂不执行」
- 试一试：按 inputSchema 渲染参数表单 → 运行 → 结果 + 耗时 + 审计提示；必填校验
- 高级调试：折叠入口（技术用户向），本期行内化
- 启用到 Agent：下拉选择目标 Agent → Toast 反馈
- 技能信息：版本/来源/更新时间/调用次数

### 2.3 我的技能（管理视角）
- 启用/停用 toggle（渐变态/灰态）
- 使用次数统计、按状态筛选
- 行内操作：试一试 / 编辑 / 导出 / 删除
- 内置/MCP 技能显示「系统托管」，不可编辑删除
- 删除被 Agent 绑定时拦截（错误码 5005）
- 空态：「从广场安装 / 创建第一个技能」双入口

### 2.4 创建技能（page-create.html，三步向导）
1. **选择创建方式**（五入口卡片）：
   - 模板库（业务推荐）：14 个按工种分组的模板，选择后预填名称/简介/工种/正文骨架
   - 空白创建：名称/描述/工种/正文
   - **导入技能包**（原内容导入升级）：选文件夹（真实导入，webkitdirectory）/ 上传 .zip / 传单个 SKILL.md / 粘贴文本；系统按内容**自动识别**内容型 vs 脚本包，渲染文件树并对带脚本的包显示「脚本暂不执行」提示——支撑外包成品技能直接导入
   - 脚本包 Scripts：SKILL.md 必需 + 脚本/资源文件树 + 「脚本本期仅存储不执行」安全提示
   - API 接入：url/method/超时/鉴权 + 入参表格动态增删 + OpenAPI 导入规划提示
2. **填写内容**：按入口渲染对应表单
3. **预览发布**：技能卡片 + 正文预览 → 发布成功页（查看我的技能 / 去广场）

### 2.5 演示技能（少量，按用户要求）
14 个 mock 技能覆盖各工种与全部来源类型：官方精选少量（售后 FAQ、合同审查要点、周报生成等），
其余为自建/导入/内置/MCP 示例，用于演示来源标识与托管规则。正式种子内容由运营后续补充。

## 3. 页面结构

```
Skill 中心（index.html）
├── 顶部 Tab：技能广场 #plaza ｜ 我的技能 #mine（hash 路由，可前进后退）
├── 技能广场
│   ├── 搜索 + 工种 chips
│   ├── 官方精选区（筛选时隐藏）
│   └── 卡片网格 → 详情抽屉（行内滑出，非独立路由）
│        ├── 试一试（内嵌面板）
│        ├── 高级调试（折叠）
│        └── 启用到 Agent（下拉）
└── 我的技能
    └── 列表行 → 同一详情抽屉

创建技能（page-create.html，独立页）
└── 步骤条：选择方式 → 填写内容 → 预览发布 → 成功页
```

跳转关系详见 `docs/ui-demo/flow-diagrams.md`。

## 4. 设计决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 广场/我的双视角替代资产列表 | 发现与管理是两种心智，混在一个列表里业务用户找不到入口 |
| D2 | 按工种而非业务域/技术形态导航 | 用户以「我是做什么的」定位自己，不以「技能是什么类型」定位 |
| D3 | 「你可以这样问」示例气泡进详情 | 业务用户靠例子理解用法，比功能描述有效；这是 v2 的签名元素 |
| D4 | 调试从顶级 Tab 降级为行内「试一试」 | 三步向导是技术工具，业务用户只需要填参数看结果；高级调试保留折叠入口不丢失能力 |
| D5 | 创建五入口，模板库标「业务推荐」 | 调研结论：创建全是双轨制，内容型是行业共识；五入口覆盖从小白到 IT 的全谱系 |
| D6 | 支持 Claude Skills 形态（SKILL.md + scripts） | 对齐行业标准形态；frontmatter 解析实现内容导入自动带出元信息 |
| D7 | 脚本本期仅存储与随包分发，不执行 | 沿用 Day 16 决策：无沙箱不执行任意脚本；UI 明示「脚本暂不执行」避免误导 |
| D8 | 官方技能只做少量演示 | 按用户要求：技能由用户自建，平台不预置大而全的种子包 |
| D9 | 视觉沿用真机 AgentOne 靛蓝渐变 token | 原型即未来生产的样子，避免评审时二次对齐视觉 |
| D10 | 内容导入升级为「导入技能包」，系统自动识别类型 | 外包/行业标准分发形态是文件夹或 zip，仅粘贴单个 SKILL.md 丢最主流导入形态；自动判型让系统判断而非让业务用户先分清 |
| D11 | MCP 工具加「发布到广场」治理（默认关闭）+ 动作型技能执行确认 | 动作型技能有真实副作用，不能与内容型同样自动上架/直接执行；与其他来源「预览→发布」流程对齐 |

## 5. 未解决的设计问题（留给 PRD 阶段）

1. **工种词表治理**：10 个工种是写死还是工作空间可配置？不同行业客户工种差异大。
2. **模板库来源**：14 个模板由谁维护、是否随版本更新、用户能否自建模板。
3. **启用到 Agent 的语义**：启用是「绑定」还是「授权可见」？多 Agent 启用后解绑路径。
4. **脚本包的未来执行方案**：沙箱选型（容器/WASM）与开放节奏，影响脚本包数据模型预留字段。
5. **API 接入的 OpenAPI 导入**：本期为规划提示，正式实现的解析范围（单接口 vs 全 spec）。
6. **使用统计口径**：调用次数按「试用」还是「Agent 对话中真实调用」计。
7. **权限**：谁可以发布到广场（全员 vs 管理员审核后上架），RBAC 课题⑥的衔接。

## 6. 治理专题（MCP 发布治理 + 动作型确认，已放一起）

> 两条同源：**动作型技能（MCP / 有副作用）与内容型技能不能同等管理**。2026-08-12 应要求合并为单一专题，方向已定，细节留 PRD。

### 6.1 MCP 供给侧发布治理

- **问题**：现真机逻辑「连上 MCP Server → 所有工具自动注册 → 自动上广场」，IT 无法控制哪些工具暴露给业务用户；Server 若暴露危险工具（删文件、写库）等于直接上架。且与「自建/导入技能要走预览→发布」不一致——唯独 MCP 工具跳过发布直接上架。
- **方向（已定）**：工具级「发布到广场」开关，**默认关闭**，IT 显式发布后才在广场可见；MCP 页管「连接+发布」（供给），Skill 广场管「启用+使用」（消费），两维正交；工具定义永远来自 MCP Server，Skill 页只消费不可编辑。
- **实现影响**：MCP 工具现为「虚拟 Skill」不落库（只进 Registry），发布状态无处存 → 需加轻量持久化表 `mcp_tool_publish(serverId, toolName, published)`。属实现层，PRD 定、原型确认后动后端。

### 6.2 动作型技能执行确认

- **问题**：发邮件、写数据、调外部系统等有副作用的技能与内容型同等管理，无安全闸。
- **方向（已定）**：动作型技能 Agent 必须先生成草稿 → 展示 → 用户显式确认后才执行（「已生成草稿，确认后发送」而非「已发送」）；结合 RBAC（课题⑥）做权限分级；动作执行一律审计留痕。
- **实现影响**：SkillDescriptor 增加「动作型」标记 + 执行确认链路 + 审计字段，随课题⑥ RBAC 一并落地。

### 6.3 留给 PRD 的待定

- 发布默认策略：默认不发布（推荐、安全）vs 默认发布（省事）——当前定默认不发布；
- 是否提供 Server 级批量发布开关（简化方案）；
- 沙箱上线后，导入/挂载脚本须先过审核才允许执行。
